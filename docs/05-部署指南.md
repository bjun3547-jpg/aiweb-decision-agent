# 部署指南（10/21 任务）

> 目标：让评委/队友用手机 4G 能打开 `https://` 公网地址，看到完整界面并跑通一次排班。
> 判据（来自 `01-执行手册.md` §五 A 的任务卡）：**公网地址手机 4G 能打开 + 断网时显示人话提示**。

## 0. 四条路线怎么选

| 路线 | 耗时 | 地址稳定 | 适合 | 代价 |
| --- | --- | --- | --- | --- |
| **A. ngrok** | **10 分钟** | ❌ 每次重启都变 | 现在就要一个能点的链接 | 电脑必须一直开着 |

## 1. 路线 A：ngrok（推荐先做这个）

### 1.1 本地先把服务跑起来

```powershell
cd F:\AIWeb\backend
..\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

看到 `Uvicorn running on http://127.0.0.1:8000` 就对了。**这个窗口不要关。**

### 1.2 另开一个窗口装 ngrok

```powershell
winget install ngrok.ngrok --source winget --accept-package-agreements --accept-source-agreements
```

> **必须加 `--source winget`。** 不加的话 winget 会先去 `msstore` 源找，
> 在部分机器上报 `0x8a15005e : The server certificate did not match any of the expected values`，
> 看起来像"装不上"，其实只是源选错了——包本身在 `winget` 源里是好的。

装完**关掉终端重开**（让 PATH 生效），然后验证版本：

```powershell
ngrok version
```

> ⚠️ **winget 里的 ngrok 版本停在 3.3.1，而 ngrok 服务端现在要求 ≥ 3.20.0。**
> 如果你直接 `ngrok http 8000`，会看到这个报错：
>
> ```
> ERROR: authentication failed: Your ngrok-agent version "3.3.1" is too old.
>        The minimum supported agent version for your account is "3.20.0".
> ERROR: ERR_NGROK_121
> ```
>
> **解法就一行：**
>
> ```powershell
> ngrok update
> ```
>
> 它会自动升到 3.39.x（约十几秒，完成后自动退出）。再 `ngrok version` 确认一下就正常了。
> 不需要手动下载 zip 覆盖 exe。

### 1.3 拿 authtoken 并绑定

1. 注册 <https://dashboard.ngrok.com/signup>（GitHub 账号可直接登录）
2. **直接打开 <https://dashboard.ngrok.com/get-started/your-authtoken>**，复制那串以 `2` 开头的字符串
   （比在引导页里找快，跳过「你想从哪里开始」那三个卡片）
3. 执行：

```powershell
ngrok config add-authtoken 你复制的那串
```

> authtoken 是账号凭证，**不要提交到仓库、不要发群里**。

### 1.4 开隧道

```powershell
ngrok http 8000
```

终端会显示：

```
Session Status    online
Account           xxx (Plan: Free)
Version           3.39.11
Forwarding        https://xxxx-xx-xx-xx-xx.ngrok-free.dev -> http://localhost:8000
```

**那个 `https://...ngrok-free.dev` 就是公网地址。** 手机 4G 打开验证。

### 1.5 注意三件事

- **免费版每次重启地址都会变**，所以录视频前要重新生成一次并记下来。
- 免费版首次访问会有一个 ngrok 的提示页，点 `Visit Site` 才进得去——**录视频时要注意别录到这一步**，或者提前点过再录。
- **电脑不能休眠**。录视频/答辩期间把电源计划改成「从不睡眠」。

### 1.6 两个必踩的坑（2026-10-21 实测）

**坑一：winget 装出来的版本太旧，报 `ERR_NGROK_121`**

见 §1.2 的提示。一句话：`ngrok update`。

这个坑很隐蔽——安装过程完全成功，`ngrok version` 也正常输出，只有真正开隧道时才报错，
而且报错文案里写的是「authentication failed」，容易误以为是 token 填错了。

**坑二：免费版的浏览器拦截页**

浏览器第一次访问 ngrok 地址，会先看到一个 ngrok 自己的页面（`You are about to visit ...`），
点 **`Visit Site`** 才能到你的应用。**这不是你的服务出问题。**

两个影响：

1. **录视频时**：提前用同一个浏览器点过一次，cookie 记住后就不再出现，录屏是干净的应用界面。
2. **写自动化脚本时**：`curl` 拿到的是拦截页的 HTML，不是你的接口响应。必须加一个请求头：

```powershell
curl -H "ngrok-skip-browser-warning: true" https://xxxx.ngrok-free.dev/api/health
```

不加这个头，`/api/health` 返回的是一段 ngrok 的 HTML，`json.load()` 会直接报错。

## 2. 路线 B：Cloudflare Tunnel（备选，不用注册）

如果 ngrok 装不上或注册不了：

```powershell
winget install Cloudflare.cloudflared
cloudflared tunnel --url http://localhost:8000
```

终端会打印一个 `https://xxx.trycloudflare.com` 地址，直接用。同样每次重启会变。

## 3. 路线 C：Docker（长期稳定）

仓库根目录已经有 `Dockerfile`、`.dockerignore`、`docker-compose.yml`。

### 3.1 本地验证镜像能跑

```powershell
cd F:\AIWeb

# 构建（国内默认走清华源，镜像约 700MB，首次 3–5 分钟）
docker build -t aiweb-agent .

# 运行：密钥从环境变量注入，不写进镜像
docker run -p 8000:8000 -e DEEPSEEK_API_KEY=sk-你的key aiweb-agent
```

打开 <http://127.0.0.1:8000>，和本地开发时一模一样。

或者用 compose（会读 `backend/.env`）：

```powershell
docker compose up --build
```

### 3.2 推到云服务器

以腾讯云轻量应用服务器 / 阿里云 ECS（Ubuntu 22.04）为例：

```bash
# 服务器上
git clone https://github.com/bjun3547-jpg/aiweb-decision-agent.git
cd aiweb-decision-agent
docker build -t aiweb-agent .
docker run -d --name aiweb \
  -p 80:8000 \
  -e DEEPSEEK_API_KEY=sk-你的key \
  --restart unless-stopped \
  aiweb-agent
```

然后浏览器打开 `http://服务器公网IP`。

> 用 80 端口是因为它不用额外开放安全组。**注意**：国内服务器绑定域名需要备案，
> 但**直接用 IP 访问不需要**——比赛演示用 IP 就够了。

### 3.3 云服务器要开放端口

在控制台的「防火墙 / 安全组」里放行 TCP 80（或你用的那个端口）。
**这一步最容易忘**，症状是「本地能开、公网打不开」。

## 4. 路线 D：Render / Railway（连 GitHub）

以 Render 为例：

2. Render 会自动识别根目录的 `Dockerfile`，选 **Docker** 而不是 Python

4. 部署完拿到 `https://xxx.onrender.com`

**注意**：免费档 15 分钟无访问会休眠，下次访问要等 30–60 秒冷启动。
答辩前 5 分钟先打开一次把它唤醒。

## 5. 密钥安全：三条铁律

公网部署最容易在这里翻车。

1. **`.env` 永不进仓库。** `.gitignore` 第 4 行 `*.env` 挡着，已用 `git log --all -- "*env"` 验证过历史里没有。
2. **密钥永不进镜像。** `.dockerignore` 里显式排除了 `.env` 和 `**/.env`，Dockerfile 里没有任何 `COPY .env`。
3. **密钥只从环境变量注入。** `docker run -e`、平台的环境变量面板、`docker compose` 的 `env_file`（本地）——三条路都行，写死进代码或镜像不行。

> 如果密钥曾经不小心提交过：立刻去 <https://platform.deepseek.com/api_keys> 吊销重发。
> 提交历史里的密钥即使后来删了文件，`git log -p` 依然能翻出来。

## 7. 常见坑

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| `winget install` 报 `0x8a15005e 服务器证书不匹配` | 默认去 `msstore` 源找，该源证书有问题 | 加 `--source winget` |
| `ngrok http` 报 `ERR_NGROK_121 authentication failed: version too old` | winget 装的是 3.3.1，服务端要求 ≥ 3.20.0 | `ngrok update`（**不是 token 填错了**） |
| ngrok 地址打开是提示页 | 免费版首次访问确认页 | 先手动点 `Visit Site`，再录视频 |
| `curl` 拿到的是 HTML 而不是 JSON | 免费版拦截页劫持了请求 | 加请求头 `-H "ngrok-skip-browser-warning: true"` |
| 本地能开，公网 404/超时 | 云服务器安全组没放行端口 | 控制台放行 TCP 80 |
| 首页白屏 | 静态文件没打进镜像 | 检查 `COPY backend /app/backend`，`app/static` 要在里面 |
| `/api/health` 返回 `configured:false` | 环境变量没传进去 | 检查 `docker run -e` 或平台的环境变量面板 |
| 排班报 402 | 余额不足 | <https://platform.deepseek.com> 充值 |
| Docker 构建卡在 `pip install` | 国内网络 | 已默认清华源；仍慢就加 `--build-arg PIP_INDEX=https://mirrors.aliyun.com/pypi/simple/` |
| 镜像拉不下来 | Docker Hub 国内不稳定 | 配镜像加速器，或把 `FROM python:3.13-slim` 换成 `FROM docker.m.daocloud.io/library/python:3.13-slim` |

## 9. CORS 要不要改？

**不用改。** `main.py` 里虽然写着 `allow_origins=["*"]` 并注释「部署时改成前端域名」，
但前端页面是由同一个 FastAPI 进程托管的（`app.mount("/static", ...)` + `GET /`），
属于**同源请求**，CORS 根本不生效。

只有当有人把前端单独部署到另一个域名时，才需要收紧这个配置。比赛期间保持现状即可。
