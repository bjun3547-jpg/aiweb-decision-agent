## 1. 选题：把它收敛成一个能赢的形态

### 1.1 你们提的方向本身是对的

「智能运筹决策 Agent」= 用户用**自然语言**描述一个业务决策问题 → Agent 把它**翻译成数学模型** → **精确求解器**算出最优解 → Agent 把结果**翻译回自然语言**并解释权衡。

这条路线在 Web 赛道里非常稀缺：绝大多数队伍做的是问答、写作、客服这类「LLM 套壳」应用。你们做的是**神经-符号混合系统**——有真算法、有可验证的最优性。**这是你们最大的差异化，务必守住：LLM 负责"翻译"，求解器负责"求解"，绝不让 LLM 直接编方案。**

### 1.2 但「通用运筹 Agent」做不完，必须收敛

**不要**做「什么运筹问题都能解」的通用平台——三周做不出来，演示也讲不清。

**要做**：**一个主场景做深 + 一个副场景跑通**。

### 1.3 场景推荐

| 优先级 | 场景 | 为什么 | 难度 |
| --- | --- | --- | --- |
| ★ 主场景 | **多技能人员排班**（护士 / 客服 / 门店 / 产线） | 痛点人人都懂；约束丰富（工时、技能匹配、连续休息、夜班上限、个人偏好）；视觉化极漂亮（甘特图 + 热力表）；CP-SAT 建模成熟 | 中 |
| ○ 副场景 | **带时间窗的车辆路径 VRP** | 地图 + 路线动画最惊艳；能体现"路径优化"这类经典运筹 | 中高 |
| △ 备选 | 生产排产 / 库存补货 / 外卖骑手调度 / 投资组合 | 都可，看你们谁熟哪个行业 | — |

**建议主场景选排班**：约束冲突最容易制造"Agent 自愈"的名场面，也最容易让评委在两分钟内看懂价值。

### 为什么用「显式状态机」而不是 ReAct 循环？

这是技术文档里最好写的加分点：

- 运筹建模的步骤是**确定的**（识别问题 → 定变量 → 定目标 → 定约束 → 求解），不需要 Agent 自己摸索
- 每一步的输入输出都能用 **JSON Schema 强约束**，幻觉可拦截
- 失败可以**回到上一步**，可复现、可评测
- 纯 ReAct 会乱跳、不可复现、无法量化

## 3. 五个能拉开差距的创新点

按「性价比」排序，前三个必做：

### ① 不可行自愈闭环（最强的名场面）

用户给的约束经常**无解**。普通做法直接报错，你们要：

1. 检测 `INFEASIBLE`
2. 用 CP-SAT 的 **不可行假设集**（软约束 + 惩罚权重）定位**冲突约束的最小集合**
3. 让 LLM 用中文说：「您的『每人每周至少休 2 天』和『周五全员在岗』冲突，最少的调整是把休息日要求放宽到 1 天，或周五放 1 人休息」
4. 用户一键采纳 → 自动重解

这一段放进演示视频，评委基本会记住你们。

### ② 人在环参数确认（防幻觉的关键）

LLM 抽出来的参数**带置信度**，低置信度的项**不直接进模型**，而是以表单形式让用户确认。

这解决了「LLM 编了个不存在的约束」这个致命问题，也让你们的 Agent 显得**可靠**而非**聪明但不可信**。

### ③ 自然语言 what-if 对比

用户说「如果小王周三请假会怎样」→ 增量重解 → 左右并排对比：目标值变化、甘特图差异高亮、成本增量。

**运筹决策的真实价值就在「权衡」，这个功能直接命中"决策"二字。**

### ④ 求解器可解释性

LP 的**对偶值 / 影子价格**翻译成人话：「现在卡住产能的是 B 产线，它的可用工时每多 1 小时，总利润能多 37 元」。

这一步把「求解器输出」变成「决策建议」。

### ⑤ 可复现评测集（大多数队伍都没有）

自建 **30–50 题 benchmark**：每道题 = 一段自然语言描述 + 已知最优解（用求解器算出来当标准答案）。

指标：
- **建模正确率** = 成功求出最优解的比例
- **参数抽取准确率** = 抽取参数与标准答案一致的字段比例
- **平均求解耗时**
- **不可行诊断准确率**

**这是把项目从"demo"抬升到"有工程验证的系统"的关键，也是评审眼里最硬的证据。** 成本不高（一两天），收益极大。

### （加分）多模态入口

上传一张排班需求表**截图**或一个 Excel → 多模态模型抽取成结构化参数。官方考核点里点名了多模态，加上就覆盖齐了。

## 4. 技术栈（保守优先，资料多、坑少）

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 前端 | **React 18 + TypeScript + Vite** | 生态最大，AI 辅助写代码效果最好 |
| UI | **Ant Design 5** | 表格/表单/卡片开箱即用，省一周 |
| 可视化 | **ECharts**（甘特用 `custom` 系列或 `heatmap`）+ 可选 AntV G6 | 国内文档最全 |
| 后端 | **Python 3.11+ / FastAPI / Pydantic v2** | 类型校验强，自动生成 API 文档 |
| 求解器 | **Google OR-Tools（CP-SAT + Linear Solver）** | 免费、开源、CP-SAT 业界最强之一；安装即用 |
| LLM | **DeepSeek（`deepseek-chat`）** | 中文好、便宜、JSON 输出稳；**封装成可替换适配层**，方便对比别的模型 |
| 通信 | **SSE 流式** | 让用户看到 Agent 的每一步，演示效果好 |
| 存储 | **SQLite** | 零配置，够用 |
| 部署 | 学生云服务器 + Docker；或 frp/ngrok 临时映射 | 在线演示是加分项 |

> ⚠️ 别用 Docker 做本地开发（你们环境里也没有）。`docker` 只在最后部署阶段需要。

## 5. 最容易翻车的六个坑

1. **最后一天一次性推代码** → 官网明文核查，直接判定「开发过程不可复现」。**从今天起每天 commit。**
2. **API Key 提交进仓库** → 第一时间 `.gitignore`，并用 `.env.example` 说明。
3. **README 写不出复现步骤** → 找个人拿新电脑（或删掉本地环境）照着 README 走一遍，走不通就改。
4. **让 LLM 直接给方案** → 立刻失去技术壁垒，沦为套壳。**必须有真求解器。**
5. **贪多**：三个场景都半成品 → 不如一个场景做到极致 + 一个跑通。
6. **拖到最后一刻才录视频** → 剪辑 + 重录至少预留 2 天。现在只剩 15 天，这条最容易踩。
