# 接入真实大模型后暴露的三个幻觉

- **日期**：2026-10-17
- **参与人**：冯璐（及队友）
- **AI 工具 / 模型**：DeepSeek（`deepseek-chat`）作为被测模型；DeepSeek Harness 作为开发助手

## 1. 我的意图

把「自然语言 → 结构化排班参数」这一步接上真实的大模型 API，跑通全链路。
不只是看它能不能跑通，而是看**它会不会出错、错在哪里**。

## 2. 我给的 Prompt

```
我们便利店下周一到周日要排班。一共 7 个店员：张伟、李娜、王强、刘洋、陈静、赵磊、孙悦。
每天分早班和晚班，晚班需要会收银的人。每个班次每天要 2 个人。
每人每周最多上 5 天班，每周至少休息 1 天。张伟下周三请假，李娜周六希望休息。
```

## 3. 三次真实失败

**幻觉一：造了一个必然无解的约束组合（最严重）**

模型给「晚班」加上了 `required_skill: "收银"`，但**没有任何一个员工被标注具备收银技能**。
于是技能匹配约束把所有人挡在晚班门外，需求永远满足不了 → 直接 INFEASIBLE。

> 这不是"排得不好"，是**从第一秒就不可能**。

**幻觉二：把 28 个班次说成了 35 个**

求解器返回 28 条排班，决策说明里写成"共 35 个班次"。数字在正文里，肉眼极难发现，
但答辩现场被评委问一句就露馅。

**幻觉三：自己算了个人均**

模型输出了"人均上班 4.0 天"，看着没错，但它**是自己算的**，不是后端给的。
这次碰巧对，下一次就不一定。

## 4. 我做了什么判断

**没有选择「改 Prompt 求它别犯错」这一条路。**
Prompt 只能降低概率，不能保证。我们的判断是：**凡是有确定答案的东西，就不能交给模型算。**

于是加了三道**确定性护栏**（不是 Prompt 技巧，是代码）：

| 护栏 | 位置 | 做法 |
| --- | --- | --- |
| 结构闸门 | `llm.chat_json()` | 强制 JSON + Pydantic 校验；失败时把错误详情回灌给模型重试一次 |
| 语义闸门 | `solver.repair_problem()` | 检测到"班次要求某技能却无人具备"时，确定性补齐并**大声提示用户确认** |
| 数字闸门 | `agent.number_guard()` | 决策说明里每个数字必须能在「问题参数 + 排班表 + 事实数字」里找到，否则标记可疑 |

**关键取舍：数字闸门一开始做错了。**

第一版太严，把**正确的 28 和 4.0 也标成了可疑**（误报）。误报比漏报更糟 ——
它会让人不再相信这个提示。修法是：把后端确定性算出的「关键数字」清单
（`fact_numbers`）也纳入白名单，同时显式规定"禁止模型做任何算术"。

现在它安静了：正确数字不报，编造数字才报。

## 5. 这件事对我们项目的意义

这三个失败如果没被发现，会直接毁掉演示：
一次必然无解的输入、一个写错的班次数、一个来路不明的人均值。

**而它们全部是在"接真模型"的第一个下午就暴露的。**
如果拖到录视频那天才发现，就没有修复窗口了。这也是我们决定今天就把链路全部打通的原因。
